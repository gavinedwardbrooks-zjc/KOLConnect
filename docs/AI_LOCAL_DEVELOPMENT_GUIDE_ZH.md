# 用 AI 在本地继续开发 KOLConnect

本指南面向编程经验不多、但希望借助 AI 修改 KOLConnect 的用户。你不需要先学完整的软件工程课程，但需要让 AI 看懂当前项目，并在每次修改后认真验证。

## 一、获取源代码

### 方法 1：下载 ZIP，最简单

1. 打开 KOLConnect 的 [GitHub 仓库](https://github.com/gavinedwardbrooks-zjc/KOLConnect)。
2. 点击 **Code**。
3. 点击 **Download ZIP**。
4. 下载完成后，将 ZIP 完整解压到普通文件夹。

例如可以解压到：

```text
C:\Users\你的用户名\Desktop\KOLConnect
```

不要直接在 ZIP 压缩包内编辑或运行项目。

### 方法 2：使用 Git Clone，适合以后更新

如果电脑已经安装 Git，可以在终端运行：

```bash
git clone https://github.com/gavinedwardbrooks-zjc/KOLConnect.git
```

Clone 会保留版本历史，之后更容易查看改动和获取更新。第一次使用 Git 时，也可以让 AI 帮你解释命令，但执行删除、重置或覆盖操作前要先确认影响。

## 二、选择能读取本地项目的 AI 工具

你可以使用任何能够检查本地项目文件夹的 AI 编程助手，例如：

- Codex
- ChatGPT Work 或可用的编程环境
- Cursor
- VS Code 加 AI 编程扩展
- 其他支持读取本地项目的 AI 编程工具

关键不是使用哪个品牌，而是该工具必须能实际读取项目文件。仅把一小段代码粘贴到聊天中，通常不足以安全修改整个项目。

## 三、先让 AI 阅读当前项目

当前仓库根目录实际提供 `README.md`，它介绍产品用途、安装方式、限制和主要文档入口。请先让 AI 阅读它，再让 AI 检查与你目标相关的 `docs/` 文档、源码和测试。

有些项目版本或开发分支可能还包含 `AGENTS.md`、`ARCHITECTURE.md`、`AI_HANDOFF.md`、`CONTRIBUTING.md` 或 `CUSTOMIZATION_GUIDE.md`。当前 `main` 没有这些文件，因此不要要求 AI 假装读取；如果将来这些文件出现，再按其说明执行。

## 四、复制这段提示词给 AI

把项目文件夹交给 AI 后，可以先发送：

```text
请先完整阅读这个 KOLConnect 项目，不要马上修改代码。

请先阅读当前实际存在的 README.md，再检查 docs/ 中与我的目标有关的文档、相关源码和测试。不要假装读取不存在的文件。

然后帮我：

1. 总结项目目前能做什么
2. 说明项目主要目录分别负责什么
3. 找出当前版本、运行方式和测试方式
4. 告诉我修改功能前必须遵守哪些数据规则
5. 不要自行改变 SQLite 的本地数据规则、Creator/CreatorAccount 模型、Campaign 状态语义和邮件语义
6. 在修改任何代码前，先告诉我你准备改哪些文件和为什么
7. 每次修改后运行相关测试
8. 不要使用 git add . 或 git add -A
9. 不要自动发布正式版本，除非我明确要求

我的目标是：
【在这里写你想增加或修改的功能】

请先只做项目审计和修改方案，不要立刻改代码。
```

## 五、开发前先做这几件事

- 备份 `%APPDATA%\KOLConnect`。这里可能包含你的本地数据库和配置。
- 最好复制一份项目，或创建单独的 Git 分支进行开发。
- 不要用重要业务数据测试删除、合并、迁移等高风险功能。
- 不要提交密码、App Secret、OAuth Secret、访问令牌、Cookie 或邮箱授权码。
- 把邮件、数据库或日志上传到公共 AI 服务前，先考虑其中是否包含个人或商业隐私。
- 将正式 Release 安装包和开发构建分开保存，避免误用。

## 六、从源代码启动

开发环境需要使用与当前依赖兼容的 Python 3.12+。打开终端，先进入项目目录，然后运行：

```bash
cd app
python launcher.py
```

如果系统提示缺少依赖，请先让 AI 阅读项目中的依赖文件和当前文档，再给出适合你系统的安装步骤，不要盲目安装来历不明的软件包。

## 七、运行测试

在项目根目录运行完整 Python 测试：

```bash
python scripts/run_python_tests.py --verbosity 1
```

修改代码后，至少运行与修改内容相关的测试；准备发布前再运行完整测试。测试失败时，不要只删除或跳过测试，应先确认是代码缺陷、环境问题还是测试本身已经过时。

## 八、不建议直接让 AI 做什么

- 不要只说“帮我优化整个项目”，然后允许 AI 大规模重构。
- 不要随意修改数据库结构或数据迁移规则。
- 不要删除数据保护、身份校验和失败时停止写入的逻辑。
- 不要让 AI 自动合并达人或猜测账号归属。
- 不要随便修改正式版本号。
- 不要自动覆盖 GitHub Release 或正式发布资产。
- 不要在不了解现有设计时重写整个项目。

## 九、一个简单的开发流程

假设你想增加一个新功能：

1. 下载或 Clone 源码。
2. 用 AI 工具打开项目文件夹。
3. 粘贴上面的项目审计提示词。
4. 告诉 AI 你想增加或修改什么。
5. 先让 AI 给出范围、风险和修改方案。
6. 确认方案后，再让 AI 修改代码。
7. 运行相关测试。
8. 自己启动开发版本并实际试用。
9. 检查改动和数据安全后，再决定是否提交。

一次只处理一个明确目标，通常比同时要求 AI 改很多功能更安全，也更容易验证。
