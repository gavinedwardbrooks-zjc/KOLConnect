# KOLConnect v0.1.2 飞书集成配置指南

本文档用于配置 KOLConnect 使用的飞书多维表格和开放平台应用。

本文档严格使用以下四张表：

1. 达人
2. 达人账号
3. Agency
4. Agency 联系人

飞书是最终 CRM 数据库。KOLConnect 负责采集、整理、审核、补全和同步，不替代运营人员对合作关系、报价、负责人和合作阶段的人工判断。

> **实现兼容提示**
>
> 本文档的字段表和飞书 AI Prompt 严格按照本次确认的字段清单编写，不新增其他字段。当前 KOLConnect v0.1.2 代码中仍存在对 `达人.来源联系人`、`达人账号.粉丝数`、`达人账号.邮箱来源` 的字段引用。使用本文 Prompt 新建飞书表前，应先确认现有生产表和程序字段映射已经一致，否则相关同步请求可能因字段不存在而失败。本提示仅说明当前实现差异，不改变本文确定的四表结构。

## 一、四表用途说明

### 1. 达人

“达人”代表真实的 KOL 主体，而不是某一个社交媒体账号。

一位达人可以拥有多个 TikTok、Instagram 或 YouTube 账号。达人表保存跨平台共用的基本资料、联系信息、合作状态、负责人和 Agency 关系。

示例：

```text
达人：Maria
├─ TikTok 账号
├─ Instagram 账号
└─ YouTube 账号
```

### 2. 达人账号

“达人账号”代表达人在某个平台上的具体公开账号。

每条记录对应一个 TikTok、Instagram 或 YouTube 主页，以“账号唯一ID”作为 KOLConnect 的账号定位与去重依据。账号表保存平台、主页、公开邮箱、抓取状态和达人关联。

### 3. Agency

“Agency”代表达人所属或合作的机构、MCN、经纪公司或资源机构。

Agency 表保存机构基本资料、公共联系方式、合作状态、负责人、资料文件，以及与达人和联系人的关联。

### 4. Agency 联系人

“Agency 联系人”代表 Agency 中的具体对接人。

联系人可以在尚未确认所属 Agency 时先独立存在，后续再关联 Agency。联系人关系和 Agency 归属应分开维护：联系人可能离职或更换，但达人所属 Agency 不应因此自动变化。

### 1. 达人表

| --- | --- | --- | --- | --- |
| 达人名称 | 单行文本（主字段） | 是，新建或空值补充 | Chrome Extension、抓取任务、人工录入、审核修改 | 达人的对外名称或常用名称。已有非空值默认不覆盖。 |

## 四、飞书开放平台配置

### 1. 创建飞书应用

1. 使用企业管理员或有权限的账号进入飞书开放平台。
2. 创建“企业自建应用”。
3. 应用名称建议填写 `KOLConnect`。
4. 设置可用范围，仅开放给需要使用 KOLConnect 的成员。

### 2. 获取 App ID

进入应用的“凭证与基础信息”页面，复制 `App ID`。

在 KOLConnect 中，App ID 用于申请飞书应用访问令牌。不要将其与 Base ID 或 Table ID 混淆。

### 3. 获取 App Secret

在同一页面获取 `App Secret`。

安全要求：

- App Secret 只填写在 KOLConnect 设置中。
- 不要写入 README、聊天记录、截图或公开代码仓库。
- 不要发送给无关人员。
- KOLConnect 的状态接口会对该值进行脱敏显示。

### 4. 开启多维表格权限

在应用“权限管理”中申请多维表格相关权限，至少需要满足：

- 读取多维表格和数据表结构。
- 读取记录。
- 新增记录。
- 更新记录。

开放平台中的权限名称可能随飞书界面调整，应以“多维表格”“记录读取”“记录写入”相关权限为准。

配置完成后：

1. 创建并发布应用版本。
2. 如果企业开启审批，等待管理员批准。
3. 将应用加入目标多维表格的可访问范围，确保应用能够读取和写入该 Base。

不要授予与 KOLConnect 无关的通讯录、消息、云文档或管理权限。

### 5. 配置 Base ID

KOLConnect 配置中的 `App Token` 对应飞书多维表格的 Base ID。

打开目标多维表格后，地址通常包含类似内容：

```text
https://example.feishu.cn/base/bascnxxxxxxxxxxxx?table=tblxxxxxxxxxxxx
```

其中：

- `bascnxxxxxxxxxxxx` 是 Base ID，也就是 KOLConnect 中的 `App Token`。
- `tblxxxxxxxxxxxx` 是当前数据表的 Table ID。

将 Base ID 填入 KOLConnect 设置中的 `App Token`。

### 6. 配置四张 Table ID

依次打开四张表，从地址栏复制各自的 `table=tbl...` 值。

| 飞书表 | 配置名称 | 当前用途 |
| --- | --- | --- |
| 达人 | `creator_table_id` | 新建或补充达人、邮件回复状态同步 |
| 达人账号 | `account_table_id` | 新建或补充账号、邮箱匹配、邮箱补全 |
| Agency | `agency_table_id` | 保存完整四表配置；当前 v0.1.2 不自动写入 Agency |
| Agency 联系人 | `contact_table_id` | 只读联系人列表和人工关系选择 |

KOLConnect v0.1.2 设置页面当前直接显示：

- 达人 Table ID
- 达人账号 Table ID
- Agency 联系人 Table ID

Agency Table ID 已在后端配置结构中保留，但当前自动同步流程不写入 Agency 表。管理员仍应在配置登记中保留正确的 Agency Table ID，避免不同环境使用错误的 Base 或表。

保存配置后，应先使用测试数据验证读取和同步，不要直接对大量正式数据执行首次同步。

## 五、KOLConnect 同步规则

### 1. 达人账号采集流程

```text
TikTok / Instagram / YouTube 公开主页
  ↓
Chrome Extension 或抓取任务
  ↓
KOLConnect 人工审核
  ↓
按账号唯一ID判断新建或已存在账号
  ↓
同步有效结果到飞书达人账号表
```

同步规则：

- `success` 记录正常同步。
- `partial_success` 记录可以同步，但应由用户确认。
- `missing_data`、`failed`、`login_required`、`platform_error` 记录跳过并保留在原任务中。
- 同一个任务中的异常记录不会阻塞其他有效记录同步。
- 已存在账号按“账号唯一ID”定位，不重复创建。
- 重复账号唯一ID会进入异常处理，不自动选择第一条记录。
- 空值不会清空飞书已有值。
- 已有非空人工数据默认不覆盖。

### 2. 达人创建和账号关联

新账号同步时：

1. KOLConnect 先按账号唯一ID检查达人账号表。
2. 如果需要新建达人，系统创建达人记录并生成达人ID。
3. 新建账号通过“达人”关联字段连接达人记录。
4. “社媒账号”可以通过飞书双向关联自动回填。

如果无法安全确认达人归属：

- 不自动合并达人。
- 可以记录“疑似达人候选”。
- 由运营人员人工确认最终达人关系。

### 3. Agency 和联系人关系

Agency 归属和联系人关系由运营人员人工确认。

KOLConnect 不应根据联系人姓名、WhatsApp、邮箱或达人名称自动推断 Agency 归属。

```text
Agency 联系人
  ↓ 人工确认
Agency
  ↓ 人工确认
达人
  ↓
达人账号
```

联系人更换时：

- 可以更新 Agency 联系人关系。
- 不应自动改变达人所属 Agency。
- 不应自动改变负责人、合作阶段或报价。

### 4. 邮件回复同步

邮件按以下关系精确匹配：

```text
邮件发件人邮箱
  ↓ 精确匹配
达人账号.账号邮箱
  ↓
达人账号.达人
  ↓
达人
```

邮件回复同步只允许：

- 更新“最近联系时间”。
- 当合作阶段为空、未联系或已联系时，推进为“跟进中”。

以下合作阶段不会被邮件同步覆盖：

- 已合作
- 已报价
- 沟通中
- 暂不合作
- 其他人工维护状态

### 5. 不自动覆盖的运营字段

同步不得自动覆盖：

- 负责人
- 报价
- 标签
- 合作阶段（邮件保护规则允许的推进除外）
- 近期合作产品
- 下次跟进时间
- 飞书已有 WhatsApp
- 飞书已有备注
- 已人工确认的 Agency 和联系人关系

## 六、字段权限规则

### 1. 系统自动写入字段

#### 达人表

- 达人名称：新建或空值补充。
- 达人ID：新建时自动生成。
- 国家/地区：新建时写入默认值，之后人工确认。
- 语言：新建时写入默认值，之后人工确认。
- WhatsApp：仅在飞书为空时补充。
- 合作阶段：新建默认“未联系”；邮件同步按保护规则推进。
- 最近联系时间：邮件回复成功匹配后更新。
- 备注：仅在飞书为空时补充。
- 社媒账号：通过达人账号关联间接回填。

#### 达人账号表

- 账号唯一ID。
- 平台。
- 主页链接。
- 账号邮箱：仅在飞书为空且未受更高优先级人工数据保护时补充。
- 最近发布时间：有可靠数据时写入。
- 最近抓取时间。
- 数据来源。
- 抓取状态。
- 归属状态。
- 达人关联。
- 疑似达人候选。

#### Agency 表

当前 KOLConnect v0.1.2 不自动创建或更新 Agency 记录。

#### Agency 联系人表

当前 KOLConnect v0.1.2 不自动创建或更新 Agency 联系人记录，仅在已配置时读取必要的联系人信息。

### 2. 人工维护字段

#### 达人表

- 邮箱
- 标签
- 近期合作产品
- 报价
- 下次跟进时间
- 负责人
- 所属机构
- 相关联系人
- 已有 WhatsApp、备注和达人名称的最终确认

#### 达人账号表

- 备注
- 迁移来源旧记录ID
- 疑似达人候选的最终确认
- 达人归属的人工修正

#### Agency 表

Agency 表全部字段以人工维护为主，包括 Agency 基本资料、联系方式、合作阶段、负责人、备注、资料文件和关联关系。

#### Agency 联系人表

Agency 联系人表全部字段以人工维护为主，包括联系人资料、归属状态、所属 Agency 和负责达人。

### 3. 禁止覆盖字段

系统同步禁止覆盖以下已有人工数据：

- 达人.负责人
- 达人.报价
- 达人.标签
- 达人.近期合作产品
- 达人.下次跟进时间
- 达人.所属机构
- 达人.相关联系人
- 达人.WhatsApp 已有值
- 达人.备注 已有值
- 达人.达人名称 已有值
- 达人账号.账号邮箱 已有值
- 达人账号.备注
- 达人账号.迁移来源旧记录ID
- Agency 表全部人工字段
- Agency 联系人表全部人工字段

合作阶段属于受保护字段。仅邮件回复同步可以在当前状态为空、未联系或已联系时推进为“跟进中”；其他状态不得自动覆盖。

### 4. 数据优先级

当本地存在不同来源的数据时，保护优先级为：

```text
人工维护
  >
人工录入
  >
审核修改
  >
系统补全
  >
系统抓取
```

即使本地数据优先级较高，飞书已有非空人工值仍应视为最终数据，不因重新抓取或重复同步而被清空或覆盖。
